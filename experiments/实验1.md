# TIGER / Semantic ID 实验方案

## 1. 实验目标

验证 Semantic ID 的构造方式、数据规模以及编码规则的跨数据集泛化能力，并使用 TIGER 生成式推荐模型统一评估推荐效果。

本阶段比较两种 Semantic ID：

- **Baseline Semantic ID**：由 3 个基于 K-Means 的 RVQ code 组成语义前缀；在本项目的 TIGER_baseline 方案中，对前三码相同的物品追加第 4 个确定性消歧 token，使完整 Semantic ID 唯一。
- **Advanced Semantic ID**：复用同一套基于 K-Means 的 RVQ codebook，通过候选搜索与全局唯一分配选择编码，保留 3 个 code，并得到唯一的 3-code ID。

注：当前实验截断没有实现 RQ-VAE。`ItemTextEncoder` 使用 TF-IDF、TruncatedSVD 和 L2 归一化生成物品向量；`ResidualVectorQuantizer` 使用多层 K-Means 逐层拟合残差 codebook。这里的 baseline 和 advanced 都属于 **K-Means/RVQ 风格的 Semantic ID 实现**，与包含神经网络 encoder、decoder、重构损失和 KL 正则的 RQ-VAE 不是同一个实现。TIGER 的 Transformer 序列模型与 Semantic ID 量化器也是两个独立部分。

注：除了"4 个确定性消歧 token"风格的baseline之外，还有一个最基础的 3-code baseline 只作为碰撞诊断结果，不作为最终公平对比结果。

### 2.1 跨数据集实验的严格定义

E5/E6 的编码规则只使用 MovieLens 1M 的物品元数据拟合：

1. 在 1M 物品文本上拟合 `ItemTextEncoder`。
2. 在 1M embedding 上拟合基础量化器或 advanced 量化器的 codebook。
3. 用已经拟合的 encoder 和 quantizer 转换 100K 物品元数据。
4. 对 100K 目录单独生成最终映射：baseline 追加 100K 目录内的消歧 token；advanced 在 100K 目录内重新执行唯一分配。
5. 只使用 100K 的 train/valid/test 交互训练和评估 TIGER。

这样可以区分“编码规则从大数据集迁移”与“推荐行为数据是否泄漏”两个问题。100K 的交互不会参与 1M encoder 或 quantizer 的拟合。

## 3. 统一实验控制

- 预处理规则、正反馈阈值、低频过滤和时间切分规则保持不变。
- 每个数据集固定同一份 train/valid/test 划分。
- TIGER 的模型结构、优化器、学习率、训练轮数、batch size、随机种子和评估 cutoff 在同一数据集的两种 Semantic ID 之间保持一致。
- 训练集只用于拟合推荐模型；验证集用于选择 checkpoint；测试集只在最终评估时使用。
- 每组实验至少记录 `Recall@K`、`NDCG@K`、`MRR@K`、训练时间、推理时间、物品覆盖率和无效/重复 Semantic ID 统计。
- 同时记录 Semantic ID 的前缀碰撞率、完整 ID 碰撞率、最大碰撞组大小和重构误差，避免只看推荐指标而无法解释结果。

## 4. 预期现象

- Advanced 预计在 100K 和 1M 的 3-code 表示中减少或消除完整 ID 碰撞，但它改变了部分物品的 code 分配，可能牺牲少量量化重构误差。
- TIGER_baseline 保留前三个 code 的语义层次；第 4 个 token 只负责区分前三个 code 相同的物品，因此不会把所有语义信息都挤进额外 token。
- 1M 相比 100K 有更多物品和交互，通常训练更慢，但编码规则统计更稳定；效果仍以实际实验为准。
- 跨数据集实验不预设一定低于同数据集实验。1M 的文本分布和物品集合与 100K 不完全一致，迁移可能带来分布偏移，也可能因为 1M 学到的表示更稳定而带来收益，因此应同时观察验证集、测试集和多次运行结果。

## 9. 阶段性结果分析

### 9.1 数据规模的影响 

同类方法在 1M 上的测试集效果高于 100K：

- baseline 的 Recall@10 从 E1 的 `0.091684` 提升到 E3 的 `0.105403`，相对提升约 14.95%。
- advanced 的 Recall@10 从 E2 的 `0.095949` 提升到 E4 的 `0.116009`，相对提升约 20.91%。

这说明 TIGER 能够从更多用户交互中学习更充分的序列规律。当前结果支持“数据规模增大有利于生成式推荐”的判断。

### 9.2 Advanced Semantic ID 的影响

在 1M 数据上，E4 全面优于 E3：

- Recall@10：`0.105403 -> 0.116009`
- NDCG@10：`0.056077 -> 0.061901`
- MRR@10：`0.041018 -> 0.045428`

这说明候选 Semantic ID 和全局唯一分配方案在数据量较大的场景下能够带来稳定收益。

在 100K 数据上，E2 相比 E1 的 Recall@10 从 `0.091684` 提升到 `0.095949`，但 NDCG@10 和 MRR@10 略低。也就是说，advanced 在 100K 上找到相关物品的能力更强，但相关物品在前几位的排序还不稳定。当前 100K 结果不能据此判定 advanced 在排序质量上劣于 baseline，因为本次实验只训练了 3 个 epoch，且生成候选受到 beam width 限制。

### 9.3 1M 编码规则迁移到 100K

E5/E6 只使用 1M 物品元数据拟合 encoder 和 quantizer，100K 的交互数据只用于训练和评估 TIGER，因此没有使用 100K 交互拟合编码规则的数据泄漏。

与同数据集实验相比：

- baseline：E5 的 Recall@10 为 `0.094883`，高于 E1 的 `0.091684`；NDCG 和 MRR 基本接近。
- advanced：E6 的 Recall@10 为 `0.102345`，高于 E2 的 `0.095949`；NDCG@10 和 MRR@10 也分别提升到 `0.054270` 和 `0.039551`。

当前结果说明从 1M 学到的物品表示和量化规则可以迁移到 100K，advanced 的迁移收益尤其明显。但 E6 的验证集指标低于 E2、测试集指标反而更高，说明跨数据集结果存在较大波动，仍需要更充分训练或多随机种子实验确认稳定性。

### 9.4 Semantic ID 冲突与重构误差

六组实验的完整 Semantic ID 碰撞率均为 0，但前三个 code 的前缀碰撞仍然存在：

| 数据和编码规则 | 前缀碰撞率 | 完整 ID 碰撞率 | 重构 MSE |
|---|---:|---:|---:|
| 100K baseline | 0.387039 | 0 | 0.001673 |
| 100K advanced | 0.387039 | 0 | 0.001898 |
| 1M baseline | 0.497811 | 0 | 0.000975 |
| 1M advanced | 0.497811 | 0 | 0.001195 |
| 100K 使用 1M 编码规则 | 0.445303 | 0 | 0.000974 |

这表明完整 ID 是否唯一不能单独决定推荐效果。baseline 使用第 4 个 token 解决同一前三码前缀下的物品区分；advanced 则在三段 code 内进行候选搜索和唯一分配。advanced 的重构误差略高，但在 1M 推荐实验中仍然取得更好的 Recall、NDCG 和 MRR，说明推荐性能还受到序列建模和生成搜索质量的共同影响。

## 10. 当前阶段结论

目前可以形成以下结论：

1. **TIGER 受益于更大的交互数据。** 1M 上的 baseline 和 advanced 都优于对应的 100K 实验。
2. **Advanced Semantic ID 在 1M 上表现出最清晰的收益。** E4 是当前六组实验中测试集三项指标最好的方案。
3. **1M 学到的编码规则具备迁移能力。** E5/E6 的测试集结果不低于对应的 100K 同数据集实验，其中 E6 的提升更明显。
4. **完整 Semantic ID 冲突率为 0 是必要的结构约束，但不是性能充分条件。** 还需要结合重构误差、候选分配方式和推荐指标进行判断。
5. **当前结果是 3 epoch 的阶段性结果。** 它适合比较当前方案的趋势，不适合当作充分训练后的最终性能。

## 11. 结果解释的限制

### 11.1 训练轮数和历史结果不可直接比较

本次六组实验统一使用 batch size 32、3 个 epoch、seed 42。此前旧版 E2 使用过 10 个 epoch、batch size 8 和 beam width 32，并得到更高的 Recall@10。由于训练配置和解码配置不同，旧结果不应直接与本次六组结果比较，也不应据此判断当前代码性能下降。

### 11.2 Top-10 推荐数量不足

本次统一使用 `beam_width=16`。由于去除用户已经交互过的物品、重复 Semantic ID 和无法严格解码的候选后，部分用户最终少于 10 个唯一推荐：

- E1 测试集平均推荐数 9.370，少于 10 条的用户数为 231。
- E2 为 9.281，少于 10 条的用户数为 255。
- E3 为 9.142，少于 10 条的用户数为 1812。
- E4 为 9.234，少于 10 条的用户数为 1621。
- E5 为 9.445，少于 10 条的用户数为 214。
- E6 为 9.039，少于 10 条的用户数为 319。

因此当前指标包含“候选不足”的影响。后续正式报告应提高 beam width 或增加候选补充策略，确保每个用户尽量获得完整的 Top-10。

### 13.5 正式结果结论

1. **Advanced Semantic ID 在同一数据规模下均取得更高测试集指标。** 100K 中 E2 相比 E1 的 Recall/NDCG/MRR 分别提高 `0.012793/0.006170/0.004155`；1M 中 E4 相比 E3 分别提高 `0.013590/0.005449/0.003185`。在统一训练到 10 个 epoch 后，advanced 的收益不再只体现在 Recall，而是三项排序指标同时提高。
2. **数据规模扩大带来稳定收益。** baseline 从 E1 到 E3 的 Recall@10 从 `0.109808` 提升到 `0.125787`；advanced 从 E2 到 E4 从 `0.122601` 提升到 `0.139377`。1M 的测试集结果在两条编码线中都高于 100K。
3. **1M 编码规则迁移到 100K 是可行的，但两种编码线表现不同。** baseline 的 E5 相比 E1 的 Recall 和 NDCG 略低，MRR 略高，整体接近同数据集训练；advanced 的 E6 相比 E2 的 Recall、NDCG、MRR 全部提高，其中 NDCG 和 MRR 提升更明显。E6 的验证集低于 E2 而测试集高于 E2，说明跨数据集结果仍有切分波动，不能只依据一次运行宣称迁移稳定。
4. **当前最佳正式结果是 E4。** 1M 同数据集 Advanced TIGER 达到 Recall@10 `0.139377`、NDCG@10 `0.073893`、MRR@10 `0.054011`。
5. **10 epoch 结果不能与旧配置直接横向比较。** 旧版记录使用过不同的 batch size、训练轮数或 beam width；本节只用于比较这六组统一配置的相对趋势。当前结果仍只使用单随机种子，后续正式论文式结论还应补充多 seed 均值和方差。
